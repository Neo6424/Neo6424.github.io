## 1. 지금까지의 보안 활동

지금까지 다양한 보안 활동을 통해 시스템 보안과 취약점 분석에 관한 경험을 쌓았다.

**[MCP Runtime Guard 프로젝트](/posts/mcp-runtime-guard/)**에서는 보안 코어 개발을 담당하며 보안 정책 엔진과 도구 실행 통제 기능을 구현했다. 이를 통해 보안 시스템을 직접 설계하고 개발하는 경험을 할 수 있었다.

**[WhiteHat School 4기](/posts/whs-av-evasion-ack2026/)**에서는 백신 탐지 우회 기법을 연구하며 Windows의 프로세스 및 메모리 구조를 학습했다. 직접 실험 환경을 구축하고 상용 백신의 탐지 특성을 분석했으며 팀 연구 결과를 ACK 2026 학부생 논문으로 게재했다.

또한 **[CVE-2024-0517 취약점 분석](/posts/cve-2024-0517-v8/)**을 통해 Chrome V8 엔진의 내부 구조와 JIT 컴파일러를 학습하고, 소스코드 분석 및 GDB를 활용한 동적 분석을 수행했다.

이러한 활동을 통해 공격 기법의 동작 원리와 이를 탐지하거나 차단하는 보안 기술을 함께 접할 수 있었다.

## 2. 활동하면서 느낀 부족한 점

### ① 취약점 분석 역량의 깊이

**부족했던 점**

공개된 취약점을 분석하고 PoC를 실행하는 경험은 쌓았지만, 취약점이 발생하는 원리를 소스코드 수준에서 완전히 이해하는 데 어려움이 있었다.

**부족했던 이유**

CVE-2024-0517을 분석하면서 V8의 내부 구조와 C++ 코드에 대한 이해가 부족하다는 것을 느꼈다. 특히 Maglev JIT 컴파일러의 동작과 메모리 할당 최적화 과정을 이해하기 위해서는 JavaScript 엔진의 구조와 메모리 관리 방식에 관한 지식이 필요했다. 또한 JavaScript 언어를 잘 모르는데 바로 분석을 시작해서 더크게 느낀거 같다.

이러한 배경지식이 충분하지 않아 취약점 관련 코드를 이해하는 데 많은 시간이 소요되었으며, PoC의 동작을 소스코드와 연결하여 분석하는 과정에서도 어려움을 겪었다.

**앞으로의 개선 계획**

앞으로는 취약점 분석에 앞서 해당 소프트웨어의 내부 구조와 관련 기술과 언어를 먼저 학습할 계획이다. 특히 C/C++와 메모리 구조에 대한 이해를 높이고 공개된 CVE의 소스코드와 패치를 분석하면서 취약점 발생 원인을 파악하는 역량이 중용한거 같다. 또한 GDB를 활용한 동적 분석을 병행하여 실제 프로그램의 동작과 소스코드를 분석하는 능력을 더 향상 시키고 싶다.

### ② 실제 취약점 발굴 경험 부족

**부족했던 점**

CTF 문제 풀이와 공개된 CVE 분석 경험은 있지만 새로운 취약점을 직접 발견하거나 Bug Bounty 프로그램에 제보한 경험은 부족하다.

**부족했던 이유**

지금까지는 CTF 문제 풀이와 이미 공개된 취약점을 분석하는 활동에 주로 집중했다. 또한 기존 취약점을 분석하는 과정에서도 어려움을 겪었기 때문에 아직 혼자서 새로운 취약점을 발견하기에는 실력이 부족하다고 생각했다. 이러한 이유로 실제 취약점 발굴에 도전하기보다는 기존 취약점을 학습하는 데 집중했다.

**앞으로의 개선 계획**

우선 CTF와 Wargame을 통해 시스템 해킹 및 리버스 엔지니어링을 공부할 계획이다. 이후 공개된 취약점의 발생 원인과 패치를 분석하고 유사한 문제가 발생할 수 있는 부분을 직접 찾아보는 연습을 진행하려고 한다. 이후에 실제 소프트웨어 분석에 도전해보고 허가된 Bug Bounty 프로그램에도 참여하여 취약점 발굴 경험을 쌓을 예정이다.

### ③ 기술문서 및 Write-up 작성 부족

**부족했던 점**

프로젝트와 실습 과정에서 학습 내용을 기록했지만 이를 다른 사람이 이해할 수 있는 체계적인 기술문서나 Write-up으로 정리하는 활동은 부족했다.

**부족했던 이유**

지금까지는 프로젝트를 완성하거나 실습 문제를 해결하는 것을 우선으로 생각했다. 분석 과정에서 새롭게 알게 된 내용이나 오류 해결 방법을 Notion 등에 기록하기는 했지만 실습이 끝난 이후에는 다음 활동을 진행하면서 기존 기록을 별도의 기술문서로 정리하는 일을 미뤘다. 그 결과 학습 내용이 정리 되어있지 않고 분석 과정과 결과를 하나의 완성된 문서로 정리한 경험이 상대적으로 부족했다.

**앞으로의 개선 계획**

앞으로는 실습과 프로젝트가 끝난 후 학습 기록을 Write-up으로 정리하는 습관을 만들 계획이다. 단순히 문제의 정답이나 해결 방법만 기록하는 것이 아니라 다른 사람도 이해할 수 있도록 작성하고자 한다. 이를 통해 학습 내용을 복습하는 동시에 기술적인 내용을 논리적으로 설명할수 있도록 만들고 싶다.

### ④ 최신 보안 논문 학습 부족

**부족했던 점**

보안 프로젝트를 진행하면서 관련 논문을 읽은 경험은 있지만 최신 보안 연구 동향을 지속적으로 파악하는 활동은 부족했다.

**부족했던 이유**

지금까지는 프로젝트를 진행하면서 필요한 기술이나 정보가 있을 때 관련 논문을 찾아 읽는 방식으로 학습했다. 또한 논문을 정기적으로 읽기 위한 일정이나 구체적인 목표를 세우지 않았기 때문에 프로젝트와 직접적인 관련이 없는 최신 연구를 접할 기회가 상대적으로 적었다.

**앞으로의 개선 계획**

앞으로는 국내외 주요 보안 학회에서 발표되는 논문을 정기적으로 읽는 습관을 만들고자 한다. 특히 USENIX Security, NDSS, IEEE S&P 등에서 발표되는 시스템 보안 및 취약점 분석 관련 논문을 중심으로 학습 하려고 한다. 매달 최소 한 편의 논문을 선정하여 정리하고 관심 있는 연구는 직접 재현해 보며 공부할려고 한다.

## 3. 향후 학습 계획

앞으로는 시스템 해킹과 리버스 엔지니어링을 중심으로 취약점 분석 역량을 강화할 계획이다.

**① 시스템 해킹 및 리버싱 공부**

CTF와 Wargame 문제를 꾸준히 풀면서 어셈블리, 메모리 구조, 바이너리 분석 역량을 높이고자 한다. 특히 AI한테 의지 하지 말고 혼자 힘으로 풀어나가며 진행할 생각이다. AI의 도움을 받아 푸는것보다 혼자 힘으로 풀어보는게 공부에 도움이 되기때문이다.

**② 실제 취약점 분석 및 재현**

공개된 CVE의 PoC와 패치를 분석해보고 격리된 환경에서 취약점 발생 원인을 직접 확인하는 실습을 진행할 계획이다. 아직은 취약점을 찾아서 Bug Bounty에 제보한적이 없다. 이후에는 허가된 Bug Bounty 프로그램에도 참여하여 실제 취약점 발굴 경험을 쌓고자 한다.

**③ 기술문서 및 Write-up 작성**

아직까지 CTF를 풀고 Write-up을 제대로 작성한 적이 없다. CTF 문제 풀이와 취약점 분석 과정을 꾸준히 기록할 예정이다. 단순히 해결 방법만 정리하는 것이 아니라, 문제에 접근한 과정과 분석 중 발생한 오류, 해결 방법까지 문서화하고자 한다.

**④ 최신 보안 논문 정독 및 분석**

국내외 주요 보안 학회에서 발표되는 논문을 꾸준히 읽으며 최신 공격 기법과 취약점 연구 동향을 파악할 계획이다.

특히 시스템 보안과 취약점 분석 관련 논문을 중심으로 연구 배경, 핵심 아이디어, 실험 방법을 정리하고, 관심 있는 연구는 직접 재현해 보면서 이해도를 높이고자 한다.

## 4. 앞으로의 목표

지금까지의 활동은 다양한 보안 기술을 경험하고 이해하는 과정이었다. 앞으로는 특정 분야에 대한 전문성을 깊이 있게 쌓는 데 집중하고 싶다. 특히 시스템 보안과 리버싱을 목표로 잡고 진행할 예정이다.
