## 1. 프로젝트 소개

MCP Runtime Guard는 AI 에이전트가 MCP 도구를 사용하는 과정에서 발생할 수 있는 민감정보 유출을 방지하기 위해 개발한 런타임 보안 시스템이다.

기존 AI 에이전트의 권한 통제는 주로 도구의 실행 허용 여부에 집중한다. 하지만 정상적인 도구라도 이전에 읽은 민감정보를 외부로 전송하는 데 사용될 수 있다는 한계가 있다.

이러한 문제를 해결하기 위해 에이전트가 읽은 정보의 민감도와 이후 도구 호출의 목적지를 함께 검사하여 정보 유출을 통제하는 시스템을 개발했다.

## 2. 담당 역할 및 주요 개발 내용

3인 팀 프로젝트에서 보안 코어(B) 개발을 담당했다. 보안 정책 판단부터 도구 실행 통제, 사용자 승인 처리, 보안 상태 저장까지 핵심 기능을 구현했다.

### ① 보안 정책 엔진 구현

- 정보를 `PUBLIC`, `INTERNAL`, `CONFIDENTIAL` 등급으로 분류하고 작업 단위로 민감도를 누적하도록 구현
- MCP 서버와 최종 목적지의 신뢰 수준을 검사하여 `ALLOW`, `ASK`, `DENY` 판정
- 기밀정보를 읽은 이후에는 공개 자료를 읽더라도 기존 민감도가 낮아지지 않도록 설계

### ② 도구 실행 및 사용자 승인 통제

- `GuardService`를 통해 MCP 도구 호출이 보안 정책 검사를 거치도록 구현
- 사용자 승인이 필요한 요청은 실행 직전에 정책과 요청 내용이 변경되지 않았는지 재검증
- 승인 중복 사용을 방지하고, 요청 결과가 불확실한 경우 자동 재전송을 제한

### ③ SQLite 기반 보안 상태 관리

- 작업 상태, 사용자 승인, 정책 판정 및 감사 기록을 저장하는 SQLite 저장소 구현
- 트랜잭션을 활용하여 승인 소비와 실행 예약 과정의 데이터 일관성 유지
- 비정상 종료 이후에도 보안 상태를 안전하게 복구하고, 기존 승인이 재사용되지 않도록 처리

## 3. 보안 검증 및 개선

개발한 보안 코어가 의도한 대로 동작하는지 확인하기 위해 `pytest`와 `Hypothesis`를 활용한 테스트를 수행했다.

정보 등급의 단조성, 정책 판정의 일관성, 사용자 승인 중복 처리 등 주요 보안 조건을 검증했으며, 예외 및 비정상 종료 상황에서도 안전하게 동작하도록 구현했다.

또한 팀 단위 통합 검증에서는 stdio 및 HTTP 기반 시험 서버를 사용하여 실제 도구 호출과 데이터 전송 여부를 확인했다.

통제된 공격 시연에서 일반 Codex는 비밀자료를 외부 서버로 전송했지만, MCP Runtime Guard를 적용한 경우 전송을 차단하여 시험 서버의 비밀자료 수신 횟수가 0회임을 확인했다.

이후 보안 취약점 진단에서 발견된 오류 메시지 정보노출 취약점 2건을 프로젝트 차원에서 수정하고 재발 방지 테스트를 추가했다.

## 4. 활동을 통해 배운 점

이번 프로젝트를 통해 AI 에이전트의 보안을 위해서는 개별 도구의 실행 권한뿐 아니라, 작업 과정에서 발생하는 정보 흐름까지 고려해야 한다는 점을 배웠다.

특히 보안 정책 엔진과 SQLite 저장소를 구현하면서 정책 판단의 정확성, 동시성 제어, 데이터 일관성이 보안 시스템에서 얼마나 중요한지 이해할 수 있었다.

또한 팀원들과 기능을 분담하고 코드 리뷰 및 통합 테스트를 진행하면서, 보안 기능을 직접 구현하고 검증하는 경험을 쌓았다.
