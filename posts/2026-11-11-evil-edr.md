# 들어가기 앞서

## EDR이란?

Endpoint Detection and Response(엔드포인트 탐지 및 대응)의 약자로, PC나 서버에서 발생하는 시스템 활동을 지속적으로 관찰하고, 사이버 공격을 탐지·조사·대응하는 보안 솔루션

## EDR의 구조

### EDR Agent / Sensor

보호할 PC나 서버에 설치되거나 운영체제에 통합되는 구성요소

주요 역할

- 프로세스 실행 감시
- 파일 생성 및 수정 감시
- 네트워크 연결 활동 감시
- 시스템 이벤트 수집
- 관리 서버로 텔레메트리 전송
- 관리 서버에서 받은 대응 명령 실행

EDR Agent는 시스템 내부를 깊이 관찰하고 대응해야 하므로 높은 권한으로 실행되는 경우가 많다.

### EDR Management Server

여러 엔드포인트에서 전송한 정보를 중앙에서 관리하는 서버

주요 역할

- 엔드포인트에서 수집한 텔레메트리 저장
- 위협 탐지 및 이벤트 간 상관관계 분석
- 보안 정책 관리
- 탐지 경고(Alert) 생성 및 관리
- 엔드포인트에 원격 대응 명령 전달

클라우드 기반 EDR에서는 이 기능을 제조사의 클라우드 인프라가 제공하기도 함

### EDR Console

보안 관리자나 SOC(Security Operations Center) 분석가가 사용하는 관리 인터페이스

주요 역할

- 전체 PC의 보안 상태 확인
- 악성 행위 탐지 결과 확인
- 특정 PC의 프로세스 실행 기록 조사
- 악성 파일 수집
- 원격 명령 실행
- 감염된 PC의 네트워크 격리

관리 콘솔 자체가 반드시 PC에 직접 접속하는 것은 아니고, 일반적으로 EDR 관리 인프라와 Agent를 통해 작업을 수행함

## EDR의 주요 기능

| 주요 기능 | 영어 | 역할 |
| --- | --- | --- |
| ① 데이터 수집 | Telemetry Collection | 시스템에서 발생하는 활동 기록 수집 |
| ② 위협 탐지 | Threat Detection | 수집된 데이터를 분석해 악성 행위 탐지 |
| ③ 사고 조사 | Investigation | 공격 과정과 피해 범위 분석 |
| ④ 사고 대응 | Incident Response | 악성 프로세스 종료, 호스트 격리 등 |
| ⑤ 위협 헌팅 | Threat Hunting | 탐지되지 않은 잠재적 공격을 능동적으로 검색 |

### 1. 텔레메트리 수집(Telemetry Collection)

엔드포인트에서 발생하는 시스템 활동을 관찰하여 수집한 데이터

수집하는 데이터의 종류

| 종류 | 수집 데이터 예시 | 보안상 목적 |
| --- | --- | --- |
| 프로세스 | 실행 파일, PID, 부모 프로세스, 명령줄 인자 | 악성 프로그램 실행 탐지 |
| 파일 시스템 | 파일 생성·수정·삭제, 경로, 해시 | 악성 파일 및 랜섬웨어 활동 식별 |
| 네트워크 | 목적지 IP, 포트, 프로세스별 연결 | C2 통신 및 의심스러운 연결 탐지 |
| 레지스트리 | 레지스트리 키 생성·수정 | 지속성(Persistence) 확보 행위 탐지 |
| 사용자 활동 | 로그인, 인증 실패, 사용자 계정 | 비정상적인 계정 사용 탐지 |
| 시스템·메모리 | 일부 메모리 관련 이벤트, 드라이버 및 시스템 활동 | 프로세스 인젝션 등 고급 공격 징후 탐지 |

### 2. 위협 탐지(Threat Detection)

수집한 텔레메트리를 분석하여 공격으로 의심되는 활동을 탐지

#### **IOC 기반 탐지**

침해가 발생했음을 나타낼 수 있는 식별 가능한 흔적

EDR은 수집한 이벤트를 위협 인텔리전스(Threat Intelligence)와 대조해 알려진 악성 지표를 찾을 수 있다.

단점은 공격자가 파일을 변경해 해시를 바꾸거나, 새로운 서버를 사용하면 기존 IOC만으로는 탐지하기 어렵다는 것이다.

#### **행위 기반 탐지(Behavior-based Detection)**

프로그램이 어떤 행동을 하는지를 분석하는 방식
프로그램의 실행흐름을 따라가면서 악성 행위를 하는지 확인한다. IOA(Indicator of Attack)의 개념이다.

장점은 알려지지 않은 악성코드라도 의심스러운 동작을 포착할 가능성이 있다는 것이다.

#### 상관관계 분석(Correlation Analysis)

하나의 이벤트가 아니라 여러 이벤트를 연결해서 분석하는 방식
개별 이벤트만 보면 정상 활동일 수 있지만, 순서와 관계를 종합하면 공격을 의삼한다.

#### 통계 및 머신러닝 기반 탐지

제품에 따라 통계 모델이나 머신러닝을 이용해 알려진 공격 패턴과 비정상적인 활동을 탐지할 수도 있다.
예를 들어 평소 실행되지 않던 프로세스 조합이나 의심스러운 파일 활동이 탐지 대상이 될 수 있다.

비정상적인 활동이 항상 악성인 것은 아니고, 악성 활동이 반드시 비정상적으로 보이는 것도 아니다.
따라서 오탐, 미탐이 발생 할 수 있다.

### 3. 사고 조사(Investigation)

어떤 공격이 발생했으며, 어디까지 피해가 확산됐는지 확인하기 위해서 아래의 3가지를 사용함

#### 프로세스 트리(Process Tree)

프로세스 간 부모·자식 관계를 보여주는 기능

보안 분석가는 프로세스 실행 경로를 역으로 추적하여 최초 침투 지점을 조사할 수 있다.
단 프로세스 트리만으로 감염을 확정할 수는 없다. 명령줄, 파일, 네트워크 이벤트 등 추가 증거가 필요함

#### 타임라인(Timeline)

특정 엔드포인트에서 발생한 이벤트를 시간순으로 재구성
보안 분석가는 이를 바탕으로 공격이 언제 시작되었고 어떤 순서로 진행됐는지 조사함

#### 포렌식 데이터 수집

EDR은 제품에 따라 엔드포인트에서 조사에 필요한 자료를 원격으로 수집할 수 있다.
사고 조사에 유용하지만, 동시에 공격자가 악용할 위험도 있음.

### 4. 사고 대응(Incident Response)

EDR은 공격을 탐지하고 조사하는 데 그치지 않고 엔드포인트에서 직접 대응 조치를 수행할 수 있다.

#### 대표적인 대응 기능

| 기능 | 설명 | 정상적인 사용 예시 |
| --- | --- | --- |
| Process Termination | 프로세스 강제 종료 | 랜섬웨어 프로세스 종료 |
| File Quarantine | 파일 격리 | 악성 실행 파일 격리 |
| File Collection | 파일 수집 | 악성코드 샘플 확보 |
| Host Isolation | 호스트 네트워크 격리 | 감염 PC의 공격 확산 방지 |
| Live Response | 원격 명령 실행 및 조사 | 프로세스, 파일, 시스템 상태 확인 |
| Script Execution | 스크립트 실행 | 여러 시스템에서 조사 작업 수행 |
| Automated Response | 자동 대응 | 특정 탐지 조건 충족 시 자동 격리 |

대표적인 기능이며 모든 EDR 제품이 동일하게 제공하지는 않음

이 논문에서 다루는 주요 기능은 라이브 대응(Live Response), 호스트 격리(Host Isolation)이다.

#### 라이브 대응(Live Response)

보안 관리자가 EDR Agent를 통해 엔드포인트에서 원격으로 명령을 실행하고 조사할 수 있도록 하는 기능
일반적인 관리자 계정보다도 시스템 내부의 다양한 자원에 강하게 접근할 수 있는 권한을 가지게 되기 때문에 공격자가 통제한다면 매우 위험하게 된다.

#### 호스트 격리(Host Isolation)

감염된 엔드포인트의 네트워크 통신을 제한하는 기능

EDR이 사용하는 관리 통신 채널을 유지하면서 다른 통신을 차단하도록 설계돼있다. 공격자가 소유한 EDR의 호스트 격리 기능을 이용해 기업의 정상 EDR 서버로 향하는 통신을 차단하고 공격자의 EDR 서버와의 연결만 유지할 수 있다는 것이 매우 위험하다고 설명하고 있다.

### 5. 위협 헌팅(Threat Hunting)

아직 경고가 발생하지 않았더라도 보안 분석가가 시스템 내부에 숨어 있을 수 있는 공격 흔적을 능동적으로 찾는 활동

일반적인 탐지와 위협 헌팅의 차이

| 구분 | 위협 탐지 | 위협 헌팅 |
| --- | --- | --- |
| 시작점 | 탐지 규칙 또는 분석 엔진 | 분석가의 가설 |
| 방식 | 자동 탐지 중심 | 능동적인 데이터 검색 |
| 목적 | 알려진 위협 및 의심 행위 발견 | 탐지되지 않은 공격 흔적 발견 |
| 예시 | 악성 PowerShell 실행 경고 | 전체 PC에서 특정 PowerShell 실행 패턴 검색 |

## AV, EPP, EDR, XDR, SIEM의 차이

논문에서 EDR과 함께 EPP가 계속 등장하여 비슷한 개념을 정리해둠

| 구분 | 정식 명칭 | 핵심 목적 | 대표 기능 |
| --- | --- | --- | --- |
| AV | Antivirus | 악성코드 탐지 및 차단 | 악성 파일 검사, 격리 |
| EPP | Endpoint Protection Platform | 엔드포인트 공격 예방 | AV, 방화벽, 공격 차단, 장치 제어 |
| EDR | Endpoint Detection and Response | 엔드포인트 위협 탐지 및 대응 | 행위 분석, 사고 조사, 원격 대응 |
| XDR | Extended Detection and Response | 여러 보안 영역의 위협 통합 분석 및 대응 | 엔드포인트·이메일·네트워크 등 데이터 연계 |
| SIEM | Security Information and Event Management | 다양한 시스템의 로그 수집 및 분석 | 로그 중앙화, 상관분석, 경고 관리 |

LotL이란?

LotL(Living off the Land)은 공격자가 새로운 악성코드를 직접 설치하는 대신, 운영체제나 시스템에 이미 존재하는 정상적인 도구와 기능을 악용하여 공격을 수행하는 기법

이미 많은 공격을 수행 가능한데 굳이라는 생각이 들김함

# 논문 리뷰

## 대상 논문

제목 : EvilEDR: Repurposing EDR as an Offensive Tool

저자 : Kotaiba Alachkar (델프트 공과대학교), Dirk Gaastra (독립 연구자), Eduardo Barbaro (델프트 공과대학교), Michel van Eeten (델프트 공과대학교), Yury Zhauniarovich (델프트 공과대학교)

## **논문을 고른 이유**

최근에 화이트햇 팀프로젝트에서 다루었던 주제인 '백신 탐지 우회 기법 및 대응 연구' 에서 다루었던 주제와 유사해 보여서 선정하게 되었다.

## 문제의식

엔드포인트 탐지 및 대응(Endpoint Detection and Response, EDR) 시스템은 지속적인 모니터링, 위협 탐지 및 대응 기능을 제공한다. 이러한 특성 때문에 기업에 널리 도입되어 보안 아키텍처의 핵심이 되었다.

여러 기업들이 신뢰하며 사용하는 EDR은 커널 수준 드라이버로 시스템을 깊이 들여다보고, 보통 SYSTEM 권한으로 동작하며, 변조 방지(tamper protection)로 관리자조차 함부로 끌 수 없게 설계되어있다. 게다가 에이전트 바이너리는 벤더의 유효한 인증서로 서명되어, 다운로드·설치 과정이 기존 보안 도구의 경고를 유발하지 않는다.

기존 공격 연구에서 주로 **EDR 회피(evasion)와 변조(tampering)**하는 방향으로 집중하고 있었다.
다만 해당 논문에서는 바라보는 시각을 바꾸어서  공격자가 EDR을 방어 도구가 아니라 공격 도구로 사용하면 어떻게 되는가 에 대해 탐구를 하고 있다.

## 핵심 아이디어

본 논문에서는 본래의 방어 목적 대신 공격 도구로 EDR 시스템을 활용하는 새로운 접근법인 EDR 용도 전환(EDRrepurposing) 을 소개한다. 저자들은 공격자가 장악한 EDR을 **EvilEDR**라 이름 붙였다. 

아이디어는 생각보다 단순하다.
상용 EDR 제품을 가져다가 공격자 자신의 서버에 연결해서  EDR 자체의 정상적인 기능을 악의적인 목적으로 사용한다. 해당 방법은 EDR 소프트웨어의 **취약점을 악용하는 것**이 아닌 EDR의 **본래 기능을 사용**하여 공격 한다는 것에 강조를 하고 있다.

다만 해당 아이디어가 실현되기 위해서는 조건이 있다. 

1. EvilEDR과 기업 EDR은 **서로 다른 솔루션**이어야 한다. 동일한 EDR의 인스턴스 두 개는 한 컴퓨터에 공존할 수 없기 때문이다.
2. 공격자가 대상 시스템에 EvilEDR을 설치하기 위한 로컬 관리자 권한을 가지고 있어야한다.

공격 흐름은 다음과 같다.

해당 조건이 모두 만족한다면 로컬 관리자 권한을 획득한 공격자는 EvilEDR로 사용할 EDR을 공급업체의 표준 설치 프로그램을 사용하여 직접 설치할 수 있다.  이후 원하는 은밀성, 유연성에 따라  자체 호스팅과 클라우드 호스팅 중 하나를 선택한다. 설치된 EvilEDR은 기업 EDR을 제거하지 않고 그 옆에서 공존하며 합법적인 EDR 기능을 그대로 악의적으로 활용한다.

논문은 이러한 접근이 3가지 이유로 매력적이라고 판단한다.

1. 단순함
EvilEDR로의 용도 전환은 소프트웨어 취약점이나 결함을 악용하지 않기 때문에 단순하다. 또한 자체 도구와 확장 기능을 개발하거나 복잡한 인프라를 유지할 필요도 없어 단순하다고 판단한다.
2. 효과적
EvilEDR는 ****EDR의 신뢰받는 지위, 운영체제에 대한 심층적 접근 권한, 풍부한 기능을 활용하므로 효과적이다. 공격자는 정상적인 소프트웨어로 가장하여 악의적인 행위를 수행하고 탐지를 피할 수 있기 때문에 효과적이라고 판단한다.
3. 적용가능
기업 EDR을 끄거나 다른 공격 도구를 설치 하는 것은 복잡하고 높은 확률로 탐지가 된다.  EvilEDR은 정상적인 기능을 사용하기 때문에 탐지 위험이 줄어든다.

또한 호스팅 방식에 따라 탐지 표면이 달랐다. 자체 호스팅 서버는 공격자 소유 IP·도메인과 통신해 탐지가 쉬운 반면, 클라우드 호스팅은 Microsoft 같은 **정상 벤더 도메인과 통신하는 것처럼 보여** 훨씬 더 은밀하다.

## 방법론

논문에서는  **MDE(Microsoft Defender for Endpoint), Elastic Defend, Sophos EDR, Trend Micro Apex One** 총 4개의 EDR을 선정하여 평가에 사용하였다. 선정된 이유는 **MITRE ATT&CK Turla 2023 평가**에 참여해 검증된 제품이었다. 

가능한 모든 두 제품 조합을 평가했으며, 한쪽은 기업 EDR(변조 방지 기능을 활성화 및 모든 보안 기능을 차단·예방 모드로 설정), 다른 한쪽은 EvilEDR(모든 클라우드 제출 기능을 비활성화 및 보안 기능을 끄거나 감사 모드로 설정)의 역할을 수행하여 평가하였다 서술하고 있다. 또한 EPP와 EDR 솔루션으로 모두 보호되며, 모든 보안 기능과 변조 방지 기능, 엄격한 탐지 및 차단 규칙이 활성화된 안전한 기업 환경을 대상으로 삼는다고 가정하여 평가를 진행 하였다. 

효과는 **MITRE ATT&CK**, **ATT&CK Evaluations**, **Turla 2023**.을 시나리오로 가정하고 EvilEDR과 APT 그룹 Turla의 공격 기법과 비교해서 보여주고 있다. 크게 Carbon이라는 백도어 멀웨어를 사용하여 스피어피싱으로 침투해 내부 웹 서버에 워터링 홀을 설치하는 단계인 Carbon 시나리오와 Snake라는 루트킷과 워터링 홀을 사용 하여  표적을 감염시켜 Exchange 서버까지 이동해 정보를 유출하는 단계인 Snake 시나리오를 사용하여 평가 결과를 보여주고 있다.

평가 방식은 Turla 기법을 기업 EDR이 탐지한 결과를 기준으로 두고 같은 목적을 EvilEDR이 달성했을때의 결과를 비교한다. 탐지 여부로 판단을 하며 텔레메트리 수집 여부로는 판단 하지 않는다.

## 평가 결과

전체적인 결과는 EDR의 정당한 기능을 그대로 쓰는 행위는 거의 탐지되지 않았고, 알려진 악성 도구·명령을 끄추는 순간 다시 탐지됐다. 

논문에서는 효과를 '기업 EDR이 탐지·차단하는가'로 정의한다. 즉 효과적은 4개의 EDR을 교차 사용하여 12회 테스트 했고 베이스라인인 원래 Turla 기법은 거의 탐지가 되었지만 EvilEDR 버전은 상당수가 미탐지 되었다는걸 뜻한다. 또한 해당 리뷰에서는 각 단계별로 모든 테스트를 나열한다면 전체적인 결과가 한눈에 들어오지 않을거 같아서 세부단계를 포함 하고 있는 핵심 단계들로 정리를 하였다.

| 단계 | 효과적 여부 | 근거 (기업 EDR 탐지 결과) |
| --- | --- | --- |
| **거점 확보** (실행·지속성·권한 상승) | 효과적 | 설치 즉시 SYSTEM·상주 → 미탐지. 단 알려진 악성 도구(mavinject 등)는 탐지 |
| **방어 회피** (EPP 탈취·호스트 격리) | 효과적 | 정상 기능이라 악성 플래그 안 됨. 격리는 사용자 네트워크 인지 위험 |
| **자격증명 접근** (하이브 덤프) | MDE만 | MDE만 하이브 추출·미탐지, 나머지 3개는 기능 없음 |
| **탐색** (시스템·계정) | 수동만 | 수동 정찰 미탐지(깊이 부족), 능동 열거(SharpHound)는 탐지 |
| **내부 이동** | 대체로 비효과 | 알려진 도구·키로거·워터링 홀 설치는 탐지, MDE 하이브 경로만 예외 |
| **수집·유출** | 효과적 | 라이브 콘솔·get file로 미탐지 반출 (Sophos 제외) |
| **명령·제어·영향** | 효과적 | 암호화 C2 + 클라우드 도메인 위장으로 미탐지, 변조 방지로 제거 방해 |

특히 중요하다고 생각한 결과는 다음과 같다.

1. EPP 장악
EvilEDR을 사용하여 EPP 서비스를 직접 설치하거나 EvilEDR 서버로 자체 EPP를 시스템의 기본 EPP로 등록해, 기존 EPP 솔루션을 덮어쓰거나 대체할 수 있다. 여기서 핵심은 Windows가 충돌 방지를 위해 한 번에 하나의 활성 EPP만 두도록 설계돼 있다는 점이다. 다른 EPP가 활성으로 등록되면 Windows Defender는 자동으로 실시간 보호를 끄고 물러난다. 공격자는 이를 악용해 의도적으로 약화시킨 자체 EPP를 기본으로 등록하고, 그러면 Defender가 스스로 비활성화되어 시스템의 유일한 보호는 무력화된 EPP만 남는다. 실험에서 대부분 기본 EPP 등록에 성공했고, 탐지나 경고 없이 Defender의 보호를 대체했다. 등록은 OS의 정당한 기능이라 사용자 알림도 뜨지 않아 탐지를 우회한다.
2. 호스트 격리
호스트 격리는 침해된 호스트의 통신을 EDR 서버로만 제한하는 EDR의 핵심 기능이다. 공격자가 이를 악용하여 침해 호스트를 EvilEDR 서버와만 통신하게 묶으면, 기업 EDR은 로그도 전송 못 하고 원격 대응도 못 한다. 기업 EDR 콘솔에서 호스트는 그저 오프라인으로 보여 악성이라고 판단하기 쉽지 않다. 다만 사용자가 네트워크 끊김을 알아차리기 쉬워서 공격자는 타이밍을 잘 잡아서 사용해야 한다.
3. **MDE의 특징?**
MDE를 EvilEDR로 쓸 때만, OS 보호를 우회해 SAM·SYSTEM·SECURITY 레지스트리 하이브를 내보내 **NTLM 해시**에 접근했고, 어느 기업 EDR도 이를 탐지하지 못했다.
이유는 다음과 같다
MDE는 Windows를 만든 Microsoft의 자사 제품이라 운영체제에 가장 깊게 접근이 가능했다. Windows가 평소 잠가두어 SYSTEM 권한으로도 복사되지 않는 SAM·SYSTEM·SECURITY 하이브를 MDE는 포렌식 목적의 정당한 기능으로 읽어낼 수 있다. 공격자가 MDE를 EvilEDR로 전용하면 이 접근 능력을 그대로 악용해서 다른 EDR이 수행 하지 못했던 NTLM 해시를 확보했다. 나머지 세 제품은 이 기능 자체가 없어 같은 공격이 불가능했다.

## 방어책

논문에서는 다층 방어를 제시하고 있다. 

예방 관점에서는 EvilEDR 설치에는 높은 권한이 필요하므로, 일반 사용자에게 로컬 관리자 권한을 주지 않고 관리자 권한은 PAM으로 통제한다는 **최소 권한 원칙** 그리고 WDAC(Windows Defender Application Control)나 SRP의 그룹 정책으로 승인된 소프트웨어만 실행되게 화이트리스팅 하는 방법을 제시하고 있다.

탐지 관점에서는 저자들은 **Sigma 형식으로 탐지 규칙**을 제공 하여 어떤 SIEM에서든 적용할 수 있게 했다. 주요 탐지 지점은 EDR 드라이버 로드, EDR 프로세스 이다. 

또한 보안팀은 PowerShell을 사용하여 EDR 프로세스와 드라이버를 탐지하는 등 수동적인 방법으로도 점검을 수행해야한다.

## 한계

논문에서 저자들은 EvilEDR이 분명한 한계를 가지고 있다고 명시하고 있다.

1. 로컬 관리자 권한이 선행 조건이다. 
공격자가 대상 시스템에 EvilEDR을 설치하기 위해서는 로컬 관리자 권한을 가지고 있다고 가정한다. 따라서 공격자는 먼저 초기 접근 권한을 획득하고, 경우에 따라 로컬 권한 상승도 수행해야 한다.
2. 다양한 실행 기법을 지원할 유연성이 부족하다.
C2 프레임워크와 달리, EvilEDR은 정상적인 소프트웨어이므로 보통 다양성이 부족하다. EvilEDR은 정상 기능에 내재된 방법으로 제한이 되므로 다양한 공격과 적응성이 떨어진다.
3. 지정된 대상과의 트래픽이 허용되어야 한다. 
EvilEDR은 관리 콘솔과의 네트워크 통신에 의존하므로 지정된 대상과의 트래픽이 허용되어야 한다. 네트워크 접근 요구사항은 EvilEDR이 자체 호스팅인지, 클라우드 호스팅인지에 따라 달라진다. 자체 호스팅 구성에는 외부 IP 주소 및 도메인과같은 공격자 인프라에 대한 접근이 필요하고, 클라우드 호스팅 구성에는 EDR 공급업체의 도메인 및 IP에 대한 접근이 필요하다
4. 네트워크 흔적과 사용자 인지는 발생 한다.
체 호스팅 서버는 공격자 소유 도메인과 통신해 탐지 가능성이 높고, 호스트 격리는 사용자가 네트워크 단절을 알아차릴 위험을 안고 있다. 논문도 EvilEDR이 다른 C2 프레임워크보다 **눈에 띄는 흔적을 남길 가능성이 높다**고 한다.
5. **은밀성은 수동적 활동에서만 유지된다.**
내장 텔레메트리를 열람하는 수동 정찰은 안 걸리지만, 더 깊은 정보를 얻으려고 **알려진 악성 명령을 능동으로 실행하는 순간 일반 공격처럼 탐지**된다.

## 확장 가능성

4개의 사용 EDR이 아닌 더 많은 EDR들로 확장하여 악용 가능성을 확인 할 수 있다. 또한 해당 연구를 바탕으로 실시간 탐지 메커니즘을 더 발전 시켜 개발 할 수 있다. EDR 드라이버와 프로세스를 대상으로 하는 정적규칙에 의존하는 대신, 머신러닝 기법을 사용하여 EvilEDR과 정상 EDR 활동을 구분하는 미묘한 행위 패턴을 인식 할 수 있도록 발전 시킬 수 있다.

## 3줄요약

- EDR(Endpoint Detection and Response) 시스템은 많은 기업들이 신뢰하며 많은 권한을 부여하여 사용하고 있는 기술이다.
- 본 논문에서는 EDR의 취약점이 아니라 정당한 기능 자체를 공격 도구로 사용하는 방법 통칭 (EvilEDR)의 공격 기법과 한계를 다루고 있다.
- 방어를 위해서는 화이트리스트 기반 추가 EDR 차단 및 보안 담당자의 실시간 탐지를 제시하고 있다.

# **느낀점**

관점에 따라서 방어 목적으로 사용하고 있는 기술이나 제품들이 오히려 공격을 하는 무기로 사용 될수 있다는 점이 새롭게 다가 왔다. 또한 방어 도구에 많은 권한이 주어진다면 해당 도구가 악의적으로 사용 될 경우 어떤 공격이 이루어 질수 있는지 어떻게 대응해야하는지 생각 해볼 수 있는 시각을 얻게 되었다.
